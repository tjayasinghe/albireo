# albireo: design document (v1)

**Status:** M0 draft for review. The equations are in the companion document,
[math.md](../docs/math.md). This document records decisions.

albireo is an open-source Python package for spectral disentangling of double- and
multiple-lined spectroscopic binaries. Given a time series of composite spectra, it infers the
orbit and the individual component spectra jointly, with uncertainties on both. The name comes
from Albireo, the gold-and-blue double star in Cygnus. The package is intended for massive-star
binary surveys, dormant black-hole and neutron-star companion searches, benchmark eclipsing
binaries, and multi-epoch survey spectroscopy (APOGEE/SDSS-V, WEAVE, 4MOST). The aim is an
openly licensed, scriptable alternative to fd3 and KOREL, described by a methods paper
(A&A/ApJS) and a JOSS paper, installable with pip and shipped with tutorials.

## 1. Prior art

| Method / code | Domain and approach | Strengths | Failure modes | Adopted / avoided |
|---|---|---|---|---|
| **Simon & Sturm 1994** (A&A 281, 286) | wavelength space; large sparse linear system, SVD, inside an orbit optimization | formulates disentangling as a linear inverse problem; natural weights and masks; arbitrary per-epoch RVs | SVD cost and memory grow rapidly with N; ill-conditioned low-frequency nullspace, no regularization; no uncertainty quantification | **Adopt** the linear-algebra formulation as the conceptual basis; replace the SVD with structured/banded solvers and priors |
| **KOREL** (Hadrava 1995, A&AS 114, 393; 2004 guide; VO service, Škoda+2012) | Fourier space; simultaneous orbit and spectra; line-strength variability | most features among established codes; decades of use | Fourier low-frequency degeneracy; closed-source FORTRAN behind a VO service requiring registration (KOREL11b, 2011), so it is neither scriptable nor reproducible offline; formal errors long criticized; no uncertainty quantification on spectra | **Avoid** Fourier space; explain undulations as nullspace (math.md §5.1) |
| **fd3 / FDBinary** (Ilijić+2004, ASPC 318, 111; ascl:1705.012) | Fourier space, C + GSL, CLI | fast, template-free, triple-capable (hierarchical), scriptable, heavily cited | requires equidistant common log-λ sampling; Keplerian-only RVs; low-frequency "bias progression" (Hensberge+2008); no uncertainty quantification anywhere; page last updated 2014, no license statement | **Avoid**; fd3 is the benchmark target for accuracy and wall-time (M5) |
| **CRES** (Ilijić) / **Spectangular** (Sablowski & Weber 2017, A&A 597, A125; 2019, A&A 623, A31; C++/Qt, Apache-2.0) | wavelength space; SVD + global optimization of orbit or per-epoch RVs | wavelength-space flexibility (weights, masks); global optimizer; handles line-strength variability | CRES abandoned (2006), takes RVs as input; Spectangular GUI-centric, hard to batch, small user community, point estimates only | direction validated; albireo adds scalability and Bayesian inference |
| **Shift-and-add grid disentangling** (González & Levato 2006; Shenar et al. 2020, A&A 639, L6 & 641, A162, LB-1/HR 6819; code: TomerShenar/Disentangling_Shift_And_Add) | iterative shift-and-add over a (K₁,K₂) χ² grid | simple, robust at low SNR, de facto standard in the massive-star and BH-candidate community; χ² maps show the K degeneracies | grid search scales exponentially in dimension; slow or stalling iteration acts as an uncontrolled implicit regularizer; light ratios are set manually, the main point of dispute in the LB-1/HR 6819 debate; no posterior; the repository has no license, so it cannot be vendored | **Adopt** the use cases and diagnostics (K₂ scans, detection maps) as built-in features; replace the machinery |
| **PSOAP** (Czekala et al. 2017, ApJ 840, 49; MIT, dormant since 2017-12) | GP joint inference in wavelength space; component spectra marginalized analytically | joint Bayesian posterior over orbit and spectra; the closest predecessor of albireo's design | dense GP covariances over epochs × pixels give cubic cost and quadratic memory, forcing small chunks; NumPy/Cython, no autodiff or GPU; unmaintained | **Adopt** the approach; **avoid** dense kernels in favour of banded precision priors and structured solves (math.md §2, §4) |
| **Seeburger et al. 2024** (MNRAS 530, 1935, "autonomous disentangling for surveys") | wavelength space; second-derivative Tikhonov + sparse LSMR solve; Nelder–Mead over RVs/q | closest methodological competitor; survey-oriented; validated on the Unicorn/Giraffe | not Bayesian, no posteriors, no GPU or autodiff; no public code as of 2026-08 | their curvature penalty is the deterministic limit of the τ·D₂ᵀD₂ prior used here, which additionally yields a posterior; benchmark against it |
| **DOLBY** (Sairam et al. 2024, BEBOP VI, MNRAS) | sum of two Doppler-shifted GPs (wavelength or CCF space) | the only active GP/Bayesian effort since PSOAP | aimed at RV precision for circumbinary planets, not spectrum recovery; code availability unverified | adjacent niche; cite and compare |
| **BiSpeD** (González, Martínez & Alejo 2024, A&A 690, A124; Martínez & González 2025, A&A 694, A32; MIT, actively maintained) | SB1: grid over q, subtract primary, cross-correlate residuals against templates | covers the low-q (≲0.5) faint-companion regime; pip-installable | not a general SB2 joint solver; template-grid dependent; grid search, no posterior | overlapping niche, covered by the SB1 K₂-scan mode (template-free, marginalized) |

Also surveyed were QER20 (Quintero & Eenens 2024, MNRAS 532, 2604; code unverified) and
single-exposure neural-network parameter recovery (Binnenfeld et al. 2025), which bypasses
disentangling. A targeted search in 2026-08 found no JAX, GPU, differentiable or Bayesian
disentangling code.

None of these codes offers (a) joint Bayesian inference of orbit and spectra with
uncertainties on both, (b) at survey scale, (c) with current engineering practice (GPU,
autodiff, tests, docs, pip). The common workaround for (a) is a bootstrap over epochs for orbit
errors and no uncertainty for the spectra. albireo targets all three, (a) first.

Conditional on the nonlinear parameters θ (orbit, light fractions, LSF, response,
hyperparameters), the component spectra enter linearly (math.md §3). With Gaussian noise and
Gaussian smoothness priors they are marginalized analytically, so NUTS samples only ~10–200
nonlinear parameters regardless of spectrum size. The spectra and their full covariance are
recovered afterwards as a conditional Gaussian. This is the linear-marginalization technique
used by celerite and starry, applied to disentangling, and it is the difference between this
package and iterative shift-and-add.

## 2. Decisions & recorded defaults

No blocking questions were open after the project brief. The following defaults were assumed
and form the decision record for review. Each is cheap to change now and expensive later.

| D27 | Scale architecture (M5) | `Problem` is a registered pytree passed as a jit argument, because closure-captured arrays trigger multi-GB XLA constant folding at scale. Probing runs as a sequential scan over probe batches with per-block gather readout, because XLA overlaps unrolled batches' live ranges (~80 GB temporary at 2×10⁵ px, measured) and non-rematerialized scans store every batch for the backward pass (~470 GB). Batch size and backward rematerialization (remat) are size-adaptive: large batch and no remat below a ~64 MB probe-output footprint, where remat doubled acceptance-test NUTS wall time for no benefit, and small batch with remat above it. The prior factor has its own small block size | benchmarks.md M5; `probe_chunk`/`remat` remain available as the CPU/GPU tuning parameters |
| D28 | Direct band assembly + closed-form gradient (M5 speedup pass) | The posterior precision is assembled per epoch from its analytic band structure. Each epoch's (i,j) block is ℓᵢℓⱼ·T(δᵢ)ᵀ·(KᵀRᵀW′RK)·T(δⱼ), a band of width ~2·(rebin support + 2·kernel radius) at a velocity-dependent offset. It is built from static rebin pair tables (`operators.rebin_pair_tables`, stored on `EpochGroup`), a vmapped kernel-sandwich pre-pass, and a `lax.scan` accumulating tent-weighted `dynamic_slice` translations into a band tensor (`assembly.band_block_tridiagonal`; math.md §4.5). This replaces 2p+1 global probe matvecs with O(band width) work per epoch (~8× per evaluation, measured). Comb probing is retained as the reference path (`assembly="probe"`) and the `validate=True` oracle. The solve stage has a custom VJP (`likelihood._solve_stage`). Cotangents come from the block-Takahashi banded selected inverse (`solver.selected_inverse_blocks`) and d̂-outer-products, removing reverse-mode differentiation through the Cholesky/solve scans. Gradients propagate through `log_likelihood`, `quad`, and `d_hat` but not through the returned Cholesky factor (a documented contract). Row translations use clip-safe `dynamic_slice` on double-padded arrays, which gives exact zero-fill for any shift and makes the reverse pass a contiguous copy rather than the scatter a gather-based translation would require. Second derivatives are reverse-over-reverse only. The forward rule recomputes its primal inline, so `jacrev(jacrev(...))` stays exact. `custom_vjp` rejects forward mode, and the forward-over-reverse `jax.hessian` was independently measured to be asymmetric on this stack even for plain autodiff, so `laplace_inverse_mass` now uses reverse-over-reverse, fixing a defect present since M3. Options recorded and not implemented are an analytic VJP through the assembly, custom-VJP band→block packing, associative-scan (parallel-prefix) Cholesky for GPU chain latency, opt-in mixed precision, and fusing the Takahashi sweep into cotangent assembly (the design-target gradient is memory-bound at 32 GB). That list is superseded by D29 and D49. D29 performed the Takahashi fusion. D49 measured the band→block packing at 0.20 s of a 10 s gradient and left it unimplemented, found that the band accumulate's transpose, absent from this list, accounted for 3.5 s, and measured a blocked Cholesky at 1.36× | benchmarks.md "Speedup pass: direct band assembly and a closed-form gradient"; band-vs-probe and VJP-vs-autodiff equality are regression-tested in tests/test_assembly.py |
| D29 | Memory pass + boundary correctness (post-D28) | The design-target gradient measured 34.0 GB against 32 GB of RAM and did not fit. Four exact reductions were made. (1) The Takahashi sweep emits the cotangent blocks directly (`solver.selected_inverse_cotangent`), so the selected inverse is never materialized. (2) The velocity-independent `G` pre-pass is batched over epochs (`epoch_chunk`), because `vmap` batches every intermediate of the chain and not only the result, which left the un-batched pre-pass at ~9 GB. Batching costs one extra backward `G` pass and is therefore applied only above a ~1 GB threshold, so small and acceptance-test-scale problems are unaffected. (3) The prior determinant uses a scalar pentadiagonal recursion (`assembly.prior_logdet`) instead of a block-tridiagonal factorization of a bandwidth-2 matrix. (4) `_pack_band`'s gather indices are hoisted out of the `lax.map` body (they are independent of the block counter) and the body is rematerialized, so reverse mode stops stacking (B,B) index and mask arrays over all K blocks. At the design target memory fell, eval 20.6 → 11.1 GB and gradient 34.0 → 18.2 GB. Because the gradient had been thrashing against RAM the times fell too, eval 26.0 → 22.2 s and gradient 111.3 → 87.4 s. (Mid-ladder gradients are 5–23% slower from the batched pre-pass's extra backward `G` pass, where memory was not the binding constraint; `epoch_chunk` trades memory for that time.) A correctness defect was fixed in the same pass: the LSF convolution wrote `G` band entries at column indices outside the model grid and the T-sandwich read them, because only the sandwich's row index was zero-filled. The defect occurs when the data-coverage margin (in model pixels) is below the kernel radius. This includes a model grid narrower than the observed range, chosen to fit a sub-region, and is reached at a fixed grid by fitting a wider LSF. At zero margin the assembled precision was wrong by 6.8e-2 relative and asymmetric by the same amount (probing is symmetric), changing the log-likelihood by −57 nats. Every fixture's margin exceeded the kernel radius, so the weights were zero where the defect occurs. `G`'s out-of-grid columns are now masked at the source. The Cholesky factor was also removed from `_solve_stage`'s outputs. A cotangent on it cannot be propagated by the closed-form rule, so `spectra_std`/`draw_spectra` gradients had been silently zero. `MarginalResult` now stores the precision and rebuilds the factor outside the custom boundary (one extra Cholesky, only for callers that request it). `build_problem` warns when a few anomalously wide native pixels set `row_support`, that is, telluric or order gaps deleted rather than masked, which increases the solver bandwidth quadratically | benchmarks.md "Memory pass and a grid-boundary defect"; the boundary case is now a fixture (`edge_covered`) compared entrywise against probing, since the log-determinant and solve compared previously average the defect out |
| D30 | Real-data ingestion path (first observed dataset: HR 6819) | Processing 51 archival ESO Phase-3 FEROS spectra led to two new modules and four fixes. `albireo.preprocess` (pure NumPy, like `data.py`) provides `fit_continuum` / `normalize`, an asymmetric-envelope-then-asymmetric-sigma-clip penalized fit of `log(flux)` on a knot grid. The fit is done in the log because a continuum is multiplicative. The measured FEROS response falls 20× over 3850–4750 Å, which a curvature penalty in linear space cannot follow (normalized flux was 30% wrong). Also, a per-pixel Whittaker smoother needs `lam ~ (L_px/2π)^4 ~ 1e12` at echelle smoothing lengths, at which the weight term is lost to rounding and the SPD factorization fails, whereas knots at 8 per smoothing length keep `lam ~ 2.6`. `estimate_ivar` applies DER_SNR (Stoehr et al. 2008, ESO's recipe) in wavelength bins, fitted to `sigma^2 = s^2/continuum`, because the ESO FEROS `ERR` column is all NaN. `select_region` / `mask_ranges` / `mask_tellurics` / `mask_spikes` mask by setting `ivar = 0`, never by deletion, which widens the row support (D29). `share_wavelength_grid` relabels per-exposure grids onto one grid by index, never by value (a `searchsorted` at a window edge errs by a whole 1.4 km/s pixel), asserting that the residual is within tolerance. It is a relabelling, not a resampling, so D4 still applies. `albireo.io` (optional `astropy`, `[io]` extra) provides `read_spectrum` for ESO Phase-3 binary tables and WCS image spectra. It takes the frame from `SPECSYS`, `v_bary` from the pipeline's keyword (`ESO DRS BARYCORR` and equivalents), and BJD_TDB at mid-exposure from the extension-header `TMID`. The pipeline's value defines the delivered frame, so astropy is used only as a fallback (agreement measured at 0.017 km/s). Each assumption it makes emits a warning naming it. `LogGrid.covering` sizes the model-grid margin as shift + kernel radius + slack. The four fixes each have a regression test. (1) `build_problem` formed `z = flux - r·base` unmasked, so a non-finite flux at a zero-weight pixel, which `data.py` documents as legal and which `normalize` produces where the continuum approaches zero, made the whole marginal likelihood `nan` through `0 * nan`. (2) Epochs of one instrument had to share a bit-identical `wave` array or `build_problem` raised an error, but a pipeline that shifts before resampling gives one grid per exposure (51 spectra, 28 grids). Grouping is now by (instrument, grid), the LSF is still keyed by instrument, and `_epoch_chunk_default` divides its byte budget by the group count. (3) `prior_logdet`'s Cholesky pivot returned `nan` below `eta/tau ~ 1e-13`, reachable by unbounded ML-II, and now has a floor. (4) The row-support warning initialized its minimum with `int64` max and was not restricted to rows the operator touches, so a region-selected epoch produced a warning quoting a meaningless value. `run_map` gained a `callback` (it reported no progress for hours, and its absolute `tol` is unreachable at survey pixel counts). The following were recorded and not fixed. Light fractions remain an input for a non-eclipsing system (D13; the K-band GRAVITY ratio does not transfer to 4400 Å). There is no jitter site yet (D15; built afterwards, see D31), so estimated inverse variances must be checked against `data_residual_zscores`. The numpyro path captures `Problem` as a closure constant rather than a jit argument, so it incurs the XLA constant folding D27 avoids for `MarginalOrbitModel.marginal` (fixed in D32) | benchmarks.md "HR 6819"; `tests/test_preprocess.py`, `tests/test_io.py`, `examples/03_hr6819_real_data.py` |
| D31 | Jitter site built (closes D15) | `EpochGroup` stores a per-epoch factor α_j. Every consumer of the weights reads `effective_w = w/α²` and none reads `w`, so the inflation enters the normal matrix, the right-hand side and the `Σ log w` term together, which makes α identifiable. It is set by `forward.with_jitter` (scalar or per-epoch, traced-safe, replacing rather than compounding, since the raw `w` is kept) and exposed as the optional θ site `log_jitter`. In the data-dominated limit `−½ log det(Λ + AᵀWA)` contributes `+p_eff·log α` against the weight term's `−N·log α`, so profiling the marginal gives `α² = χ²/(N − p_eff)` with `p_eff = tr[(Λ + AᵀWA)⁻¹AᵀWA]`, the variance estimate corrected for effective degrees of freedom and not `χ²/N`. The naive estimate (whiten the residuals, take their standard deviation, rescale ivar) is low by `√(1 − p_eff/N)`, 4.6% in the weak-prior fixture. The size of the correction depends on the run, and `p_eff` is not `n_comp · n_pix`. On HR 6819 an oversampled grid and a fitted smoothness prior gave `p_eff ≈ 2900` against 19,876 model pixels, about the resolution-element count, so the correction there was 0.4%. Inverting the two estimators, `p_eff = N[1 − (sd/α̂)²]`, gives a diagnostic, otherwise awkward to obtain, of how much of the spectrum the data constrain. The regression test injects a known ivar scale error and recovers it to 0.8%. Two limits are documented at the function. A diagonal inflation cannot represent a residual correlated across pixels, so a jitter fitted against systematics (continuum, LSF mismatch, line-profile variability) yields a wider but still biased orbit. `data_residual_zscores` now whitens by the assumed weights, jitter included, so after a jitter is fitted the z-score sd is ≈1 by construction and the remaining diagnostic is the residual's shape, not its scale. Measured on HR 6819, the result is a caution, not an improvement. Per-epoch α ranges over 1.11–3.61 (the worst exposure has 1/13 of its nominal weight) and gains +19,763 nats over one shared α, and the residuals whiten to sd 0.997 as expected. The period moves by 174× the no-jitter formal error, away from the published value, because the noisiest exposures cluster in the first third of the baseline (`corr(α, phase) = −0.25`) and downweighting them removes the period leverage at one end. Both fits are optima under their own weights (cross-evaluated: +10,622 nats one way, +3,835 the other), so the noise model selects the optimum and the shift is not a defect. Window-to-window disagreement in period went from 5.6× to 13.1× the combined formal error. The standing recommendation is extended: quote the spread across independent windows and across defensible noise models | `tests/test_jitter.py`; math.md §3.2a; benchmarks.md "The jitter site" |
| D32 | numpyro path traces the problem (closes D30's open item) | `MarginalOrbitModel.model()` takes the base `Problem` as an optional model argument and exposes it through a `model_args` attribute on the returned closure. `run_map` / `laplace_inverse_mass` / `run_nuts` resolve the arguments (explicit > model attribute > none) and pass them through numpyro as traced jit arguments, using `initialize_model(dynamic_args=True, model_args=...)` for the MAP/Laplace potential and `MCMC(jit_model_args=True)` for the NUTS sample loop. This extends the D27 contract to every jitted entry point with no call-site changes. On the m5 ladder (50 epochs, CPU, value+grad of the potential) compile time fell 20.9 → 0.8 s at 31.7k px and 10.8 → 0.8 s at 74.3k px. The closure build folded 1.99 GiB of derived constants into the executable at 31.7k px (+1.35 GiB process peak at compile, XLA's slow-folding alarm triggered by `f64[50,126936]` scatter-adds), while at 74.3k px XLA's folding guards skipped the largest folds. The memory cost therefore depends on scale- and version-dependent heuristics, a reason to remove the exposure rather than rely on the guard (D27 measured ~80 GB from the same mechanism at the design target). Results are unchanged: potential and gradient agree to all printed digits, run_map paths to float tolerance, and Laplace exactly. A model called with no argument (plain numpyro utilities, `log_density`) falls back to the closure, which is correct but incurs the compile-time cost at scale. `model_args=()` selects that path explicitly | benchmarks.md "D32"; `tests/test_inference.py` jaxpr-consts probe + path-agreement tests; `scripts/d32_model_args_bench.py` |
| D33 | Response θ-site (closes D7's deferral, the per-epoch continuum treatment) | This adds `forward.with_response` and the optional θ site `response` (`(n_coef,)` shared or `(n_epochs, n_coef)` per-epoch, laid out as the `light` site). The response enters the targets `z = y − r(R·1)` and the sandwich weights `w r²` as well as the operator, which is why D7 deferred it. `R·1` is response-independent and now stored per group, so `z_new = z_old + (r_old − r_new)·R·1` rebuilds the target exactly without the raw fluxes (re-masked, so D30's `0·nan` defect cannot recur). `Σ log w` is unchanged (the noise is defined on the data), and the site replaces rather than compounds, like the jitter. The traced Clenshaw recursion matches `np.polynomial.chebyshev.chebval` operation for operation, so the swap equals a fresh build (`r` bitwise equal, marginal to rtol 1e-12). ## 3. Data model

The core takes arrays. Instrument I/O is out of scope (one thin loader utility only).

```
EpochData:                      # one observed spectrum
    wave        (N_j,) float64  # native wavelength grid, Å (vacuum or air: declared, not guessed)
    flux        (N_j,) float64  # continuum-normalized
    ivar        (N_j,) float64  # inverse variance; 0 = masked
    mask        (N_j,) bool     # optional convenience; folded into ivar
    bjd         float           # BJD_TDB mid-exposure
    v_bary      float           # barycentric correction velocity [km/s]
    instrument  str             # key into the LSF/response tables

Dataset: list[EpochData] + frame flag ("topocentric" | "barycentric"), validation, summary stats
```

Internally the dataset is packed into padded/ragged JAX arrays batched by instrument. Chip
gaps, cosmic-ray hits and interstellar lines are all `ivar = 0`, with no special cases
downstream (weights and masks are applied in every operator and every solve).

## 4. Model & inference architecture

The model in one equation (derivations in math.md §1–3) is, per epoch,
`m_j = diag(r_j) · R_j · [1 + Σ_i ℓ_ij · B_j · T(δ_ij) · d_i]`, i.e. shift → LSF-convolve →
rebin-to-native → response, which is linear in the stacked deviation spectra `d`. The spectra
`d` are marginalized analytically, θ is sampled with NUTS, and `p(d | y)` is recovered as a
mixture of conditional Gaussians over posterior θ draws.

**Parameter split.**
- Linear (marginalized): component deviation spectra `d_i`, ~10⁵–10⁶ numbers that are never
  sampled.
- Nonlinear θ (sampled): orbit (~5–8), light fractions (0–N_c·J), LSF widths (per instrument),
  response coefficients (J·(order+1)), jitters (≤J), prior hyperparameters (≤2·N_c). Typically
  20–250.

**Modes.** All share one code path. A mode is a choice of velocity law and what is held fixed.
1. SB2/SB3 Keplerian joint inference (the primary mode).
2. Free per-epoch velocities (diagnostic).
3. Fixed-orbit linear solve (M2 milestone; also the "spectra now" utility).
4. SB1 + faint companion K₂ scan → Δlogℒ detection maps + recovered secondary spectrum
   (math.md §6), vmapped over the grid.

**Outputs** (`FitResult` / `PosteriorResult`): θ posterior (arviz-compatible), conditional
spectra draws + pointwise bands + banded covariance info, whitened residual diagnostics,
degeneracy report (low-k variance spectrum, response–spectrum covariances), sensitivity
forecast utility.

## 5. Degeneracy policy

The derivations are in math.md §5. A real degeneracy is never regularized away without notice.
It is made proper with an explicit prior scale and reported, and where only external
information resolves it, the user is required to choose.

| Degeneracy | Policy |
|---|---|
| Low-frequency mode exchange ("undulations") | proper priors with documented scale; posterior covariance reports inflation; `sensitivity_forecast()` for observing strategy |
| Light ratio ↔ line depth | explicit choice required: `Fixed` / `Free(prior=...)` / `PerEpoch(eclipse model)`; the docs explain what breaks it |
| γ ↔ common shift | γ ≡ 0 default; post-hoc template measurement; free-γ requires an informative prior |
| Response ↔ broad features | low default order; covariance reported |

## 9. Non-goals (v1) and v2 extension points

Not in v1: GUI; Fourier-space methods; time-variable component spectra (pulsations/spots);
emission-line-specific models; apsidal motion; exhaustive instrument I/O.

The extension points designed for v2 are as follows. Each component has its own velocity-law
interface and a (future) time-dependence interface, so a pulsating component would subclass the
component protocol without changes to the solver. The LSF is an operator slot (Gaussian →
tabulated is a swap). The Keplerian core is a standalone module shared with a future
differentiable eclipsing-binary package for joint light-curve + RV + disentangling fits.
Strategies A/B share one solver interface, to which new structured solvers can be added.
